## 1. Бэкенд (`04_Backend/server`) — в хорошем состоянии

Проверил слои domain / data / presentation / DI крест-накрест.

- **DI (`AppModule.kt`)** — все классы репозиториев и usecase'ов, которые там регистрируются,
  реально существуют (часть лежит по нескольку в одном файле: `CommentRepositoryImpl`,
  `ReminderRepositoryImpl`, `AttendanceRepositoryImpl` в `SocialRepositoryImpl.kt`;
  `InvitationRepositoryImpl` в `FriendRepositoryImpl.kt`; `PinAnimationRepositoryImpl`
  в `BusinessRepositoryImpl.kt`; `CapsuleRepositoryImpl` в `GameRepositoryImpl.kt`;
  `XpRepositoryImpl` в `QuestRepositoryImpl.kt`). Несоответствий нет.
- **domain** (`Models.kt`, `Repositories.kt`, usecase'ы) — поля моделей и сигнатуры
  репозиториев совпадают с тем, как их вызывают usecase'ы. Проверил Event/Ticket/
  TimeCapsule/GameProfile/Quest и т.д. — расхождений не нашёл.
- **data (Exposed)** — используется корректный современный API Exposed 0.53
  (`selectAll().where{}`, `andWhere`, `insert{}`, `newSuspendedTransaction`), маппинг строк
  совпадает со схемой `Tables.kt`.
- **presentation (Ktor 2.3.12)** — роуты вызывают usecase'ы с правильными аргументами,
  sealed-Result разбирается полностью, DTO-мапперы на месте.

**Вывод:** определённых ошибок компиляции в проверенных слоях нет. Пометка в README
«компиляция не запускалась» — следствие окружения (не было сети для Gradle), а не битого
кода. Что нужно для подтверждения: `cd 04_Backend/server && ./gradlew build test` на JDK 17,
поднять `docker compose up --build`, проверить `GET /events` и `POST /auth/register`.

Оговорка: я прочитал центральные файлы, не все ~50. Без компилятора 100%-гарантии нет.

## 2. Клиент (`02_Code`) — ГЛАВНАЯ НАХОДКА: осиротевшие модули

Восемь целых фич реализованы в коде, но **выключены из сборки**: у них нет
`build.gradle.kts`, их нет в `settings.gradle.kts`, и `composeApp` на них не ссылается.
Компилятор Kotlin их даже не видит → эти экраны не собираются и не попадают в приложение.

Осиротевшие фичи (есть исходники-экраны, но не модули):

| Фича | Что внутри (примеры экранов) |
|---|---|
| `feature/quest/ui` | QuestCatalogScreen, QuestDetailScreen, QuestCheckInScreen |
| `feature/payment/ui` | PaymentScreen, MyTicketsScreen, TicketDetailScreen, BookingSuccessScreen |
| `feature/game/ui` | GameHubScreen, LeaderboardScreen, AchievementsScreen, WrappedScreen, TimeCapsuleScreen |
| `feature/business/ui` | BusinessPromo/Reg(1-4)/Status, BusinessOrganizer/EventList/Analytics |
| `feature/invite/ui` | FriendsScreen, CreateInviteScreen, InviteCardScreen, FollowRequests, PeopleYouMayKnow |
| `feature/chat/ui` | ConversationListScreen, ConversationScreen |
| `feature/moderation/ui` | ReportScreen, MyReportsScreen, AccountRestrictedScreen |
| `feature/settings/ui` | Account/DataExport/DeleteAccount, Privacy/Sessions/Notifications/Appearance |

Эти модули зависят от `com.eventmap.theme.*` (т.е. `core.ui`), Voyager и Koin — то есть
вписываются в стандартный шаблон фич-модуля.

**Что я сделал (безопасно, ничего не ломает):** создал готовые черновики
`build.gradle.kts` для **всех 8** осиротевших модулей:
- `quest/ui`, `payment/ui` (с `core.network` — могут дёргать сеть)
- `game/ui`, `business/ui`, `invite/ui`, `chat/ui`, `moderation/ui`, `settings/ui`
  (только `core.ui`/тема — сети не импортируют)

Файл `build.gradle.kts` в директории, которой нет в `settings.gradle.kts`, Gradle вообще
не читает — поэтому это аддитивно и текущую сборку не трогает, пока модуль не активируешь.
На первой сборке после активации сверь набор зависимостей с реальными импортами (если
экран тянет viewmodel/модель из другого модуля — добавь соответствующий `projects.*`).

**Остальные слои клиента** (map, auth, event, profile, feed, search, video, example +
core) подключены корректно и взаимоувязаны.
