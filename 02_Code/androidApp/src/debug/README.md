# Изолированное UI-превью

В debug-сборке есть второй ярлык **EventMap UI Preview**. Это проверка общего
`VideoFeedLayout` и `BottomNavBar`, которые использует основное приложение,
с локальными тестовыми данными. В release этот Activity, ярлык и ролик не входят.

Превью не открывает навигацию основного приложения, не получает токены,
не вызывает репозитории и не публикует события. Автор, подпись, 28 лайков
и 4 комментария — явно помеченные фикстуры только этого экрана. Кнопки
переходов показывают пояснение; лайк меняется только в памяти превью.
В основном приложении данные и действия по-прежнему связаны с API.

## Запуск

Из каталога `02_Code`:

```sh
./gradlew :androidApp:assembleDebug
adb install -r androidApp/build/outputs/apk/debug/androidApp-debug.apk
```

На устройстве открыть **EventMap UI Preview**, а не обычный ярлык EventMap.

## Проверки

- «Карточка»: локальный восьмисекундный MP4 воспроизводится настоящим ExoPlayer.
  Шкала и таймер поступают из плеера, а не из отдельной анимации.
- Пауза: кадр и время останавливаются; повторное нажатие продолжает ролик.
- Лайк: переключается 28/29 и меняет цвет иконки, без запроса на сервер.
- «Пусто»: пояснение пустой ленты и кнопка обновления.
- «Ошибка»: сообщение ошибки и повторная попытка, без подмены ленты моками.
- Проверить читаемость подписи, карточку связанного события и нижнюю навигацию.

Это не проверка авторизации, сети, загрузки/обработки пользовательского видео,
обсуждений и переходов между рабочими экранами. Для них нужен отдельный прогон
обычного EventMap с доступным сервером и тестовой учётной записью.

## Происхождение ролика

`res/raw/preview_reel.mp4` — оригинальная процедурная анимация футбольного поля,
без чужих изображений, музыки и сетевых ресурсов. Исходник генератора:
`tools/generate-preview.swift` (встроенные macOS AVFoundation/CoreGraphics).
Для воспроизведения генерации указать **новый** путь, существующий файл
генератор намеренно не перезаписывает:

```sh
swift androidApp/src/debug/tools/generate-preview.swift /absolute/new/path/preview_reel.mp4
```

## Проверка сборки редизайна, 12 ноября 2026

- Android `:androidApp:assembleDebug` — успешно.
- iOS `:composeApp:linkDebugFrameworkIosSimulatorArm64` — успешно;
  запуск на iPhone/iOS-симуляторе этим не подтверждается.
- `:common:core:ui:desktopTest` — 3 теста.
- `:common:feature:map:ui:desktopTest` — 6 тестов.
- `:common:feature:event:ui:desktopTest` — 19 тестов.
- Итого 28 тестов, без падений и пропусков.
- `:androidApp:processReleaseMainManifest` — успешно; в итоговом release-манифесте
  нет `DesignPreviewActivity`.

Оформление экрана, локальное переключение лайка, пустая лента и состояние
ошибки проверены в Android-эмуляторе API 36. Полный сетевой прогон пока
не подтверждён: в предыдущей проверке запрос авторизации завершался таймаутом.
После разблокировки Mac проверка локального MP4 завершена в Android-эмуляторе:
видео воспроизводится, длительность отображается как `00:08`, пауза удерживает
один и тот же кадр и время, повторное нажатие возобновляет движение и таймер
(наблюдалось `00:04 / 00:08`). Ошибок `AndroidRuntime` в последних 300 строках
лога после проверки нет. Это подтверждает локальное воспроизведение, но не
доставку роликов с сервера или воспроизведение на iOS.
