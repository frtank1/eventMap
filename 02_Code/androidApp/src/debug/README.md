# Изолированное UI-превью

В debug-сборке есть второй ярлык **EventMap UI Preview**. Это проверка общего
`VideoFeedLayout` и `BottomNavBar`, которые использует основное приложение,
с локальными тестовыми данными. В release этот Activity, ярлык и ролик не входят.

Превью не открывает навигацию основного приложения, не получает токены,
не вызывает репозитории и не публикует события. Автор, подпись, 28 лайков
и 4 комментария — явно помеченные фикстуры только этого экрана. Кнопки
переходов показывают пояснение; лайк меняется только в памяти превью.
В основном приложении данные и действия по-прежнему связаны с API.

## Запуск

Из каталога `02_Code`:

```sh
./gradlew :androidApp:assembleDebug
adb install -r androidApp/build/outputs/apk/debug/androidApp-debug.apk
```

На устройстве открыть **EventMap UI Preview**, а не обычный ярлык EventMap.

## Проверки

- «Карточка»: локальный восьмисекундный MP4 воспроизводится настоящим ExoPlayer.
  Шкала и таймер поступают из плеера, а не из отдельной анимации.
- Пауза: кадр и время останавливаются; повторное нажатие продолжает ролик.
- Лайк: переключается 28/29 и меняет цвет иконки, без запроса на сервер.
- «Пусто»: пояснение пустой ленты и кнопка обновления.
- «Ошибка»: сообщение ошибки и повторная попытка, без подмены ленты моками.
- Проверить читаемость подписи, карточку связанного события и нижнюю навигацию.

Это не проверка авторизации, сети, загрузки/обработки пользовательского видео,
обсуждений и переходов между рабочими экранами. Для них нужен отдельный прогон
обычного EventMap с доступным сервером и тестовой учётной записью.

## Происхождение ролика

`res/raw/preview_reel.mp4` — оригинальная процедурная анимация футбольного поля,
без чужих изображений, музыки и сетевых ресурсов. Исходник генератора:
`tools/generate-preview.swift` (встроенные macOS AVFoundation/CoreGraphics).
Для воспроизведения генерации указать **новый** путь, существующий файл
генератор намеренно не перезаписывает:

```sh
swift androidApp/src/debug/tools/generate-preview.swift /absolute/new/path/preview_reel.mp4
```

## City Preview: карта → персонаж → встреча

### Обновление Nūrjol Garden, 16 ноября 2026

Общий мобильный runtime получил новый дневной/ночной материал, озеленение,
реальные CC0-кашпо/болларды Quaternius и автоматическое снижение качества при
устойчиво медленных кадрах. Детальный квартал Байтерека теперь не пропадает после
загрузки сетевых тайлов. Редактор персонажа и маршрут прогулки свободны от клумб.
Весь город, обложки-шарики, адреса/входы и callbacks создания событий сохранены.

156 JS-тестов, 22 desktop-теста карты, экспорт моделей и Android debug-сборка
проходят. В API 36 / WebView 133 проверены новая сцена, адрес Байтерека, выбор
основного входа и перенос его координат в форму локальной встречи. После
разблокировки Mac инструмент перестал принимать нажатия: результат добавления
этой встречи и FPS финального APK на Android не подтверждены. Финальная сборка
установлена; открыть **EventMap City Preview** для следующего прогона.

Браузерный контроль: около 30 FPS, p95 около 34 мс при лимите 30 FPS и DPR 1.35.
Это не измерение физического телефона. Серверная публикация/обложка на втором
устройстве, GPS друзей, iOS и длительный тест нагрева этим прогоном не проверялись.
Подробности и воспроизводимый бенчмарк: `game-city/README.md`.

Следующие абзацы — история предыдущих срезов, не статус этой финальной сборки.

Актуальный срез: **вся Астана**, 19 ориентиров и общий стиль сетевой застройки.
Кнопка «Вся Астана» открывает обзор; «Сцена → Перейти к зданию» — список мест
и переходы на север/восток/запад. Встроенные кварталы Байтерека/Арены остаются
резервом, не ограничивают перемещение. 10 публичных фикстур: разные категории,
набор участников и сигнал. Нажатие на землю/здание открывает место и локальное
создание встречи, которая появляется на карте; завершение её убирает. Это память
Activity, не публикация в API. При смене процесса эти события не сохраняются.

Все 19 ориентиров теперь в обновляемом manifest-пакете engineVersion=2; API формы
не менялся. Сборка Android и 39 JS-тестов проходят, desktop карты/событий — 27 тестов.
WASM публикации/медиа — 8 падений, не исправлены и не скрыты. Проверка нового
экрана эмулятора была прервана потерей доступа к окну; установку APK не считать
доказательством успешного UI/сетевого прогона. Сначала проверялся API 26 с работающим
DNS tiles.openfreemap.org; к финальной установке активным стал emulator-5556
(Medium Phone API 36). Свежий APK установлен на него успешно, но управление окном
снова пропало до запуска City Preview. Исторические UI-проверки ниже не заменяют
приёмку текущей сборки.

Третий debug-ярлык **EventMap City Preview** открывает общий `GameCityView`
без авторизации, запросов разрешений и записи в API. Он имеет отдельный
`taskAffinity`, чтобы Android не возвращал вместо него существующую задачу
с регистрацией основного EventMap. В release обоих PreviewActivity нет.

В рабочей карте метки передаются из API; этот экран отдельно задаёт `preview:true`
и десять вымышленных публичных событий по городу. Площадка, игроки, имена и участие
демонстрационные. Это не подтверждение существования футбольного поля в этой точке.

Порядок проверки:

1. Открыть City Preview, проверить Байтерек и масштабирование.
2. «Мой образ»: изменить одежду, кожу, волосы, причёску/шапку, рюкзак;
   закрыть и открыть приложение — образ должен сохраниться на устройстве.
   «Лицо / ¾ / Сзади» показывают новый детализированный персонаж с разных сторон.
   «Шаг» включает походку на месте: проверить сгибы коленей/локтей и опору стопы.
   На узком экране обувь должна оставаться выше панели; ночью лицо читается
   благодаря свету редактора. Это локальная визуализация, не GPS или чат-ИИ.
3. Выбрать футбольную метку либо «Рядом» → встреча.
4. Развернуть карточку, запустить и остановить локальный ролик.
5. «Присоединиться · демо» меняет 4 на 5; отмена возвращает 4.
6. Закрыть карточку, проверить день/ночь и возврат к управлению картой.

Проверено 12 ноября: Android debug-сборка; 13 JS-тестов; 7 desktop-тестов
модуля карты; 3 desktop-теста UI; компиляция модуля карты для iOS Simulator ARM64.
Это не запуск приложения на iOS и не тест на физическом телефоне.

В Android API 36 подтверждены отрисовка встроенной 3D-модели, редактор и изменение
одежды, переход с метки в карточку, запуск локального видео, переключение участия.
При прогоне устранены нулевая высота canvas в WebView и возврат ярлыка в регистрацию.
Обнаружен выход видео за границы карточки: Android PlayerView переведён на
TextureView с ограничением области отрисовки. Причина выбора поверхности и её
компромиссы описаны в [документации Media3](https://developer.android.com/media/media3/ui/surface).
Энергопотребление/плавность этого варианта на физических устройствах ещё не измерены.

После установки исправленной сборки повторно проверено на Android API 36:
видео остаётся внутри своего прямоугольника, текст и кнопки не перекрывает;
пауза сохраняет кадр между двумя наблюдениями. Участие переключается 4 → 5,
отмена возвращает 4. Скрин `event-video-phone.png` показывает карточку
после присоединения с остановленным роликом.

Ограничение среды: эмулятор возвращает `unknown host tiles.openfreemap.org`;
он не загрузил улицы и обычные дома. В браузере на Mac тот же квартал загрузился.
Встроенный резерв сейчас содержит основные модели, а не полный офлайн-город.
Настройки DNS/безопасности устройства при проверке не менялись.

Нет синхронизации аватара с сервером, живого местоположения друзей или записи
участия этой демо-встречи в API. Реальную связку авторизация → событие → участие
нужно проверять отдельно на доступном сервере.

Скриншоты хранятся локально в `androidApp/build/reports/city-preview/` (Git ignore).

### Следующий срез: игровой квартал Байтерека

Квартал теперь встроен в общий WebView runtime: 278 зданий из сохранённого
OSM-снимка, дорожки, зелень, единые фасады, дневная и ночная палитра.
Описанная выше ошибка DNS больше не мешает отображению **этого квартала**;
остальной город по-прежнему зависит от сетевых тайлов.

В City Preview: **Сцена** → подсветка / салют / снег. Салют однократный, 6 секунд.
**Прогулка · демо** показывает движение аватара без GPS; **Обзор** останавливает его.
**Качество** меняет бюджет; **Показать показатели** включает фактические FPS,
p95 интервала кадров, draw calls и число треугольников. Показатели браузера
нельзя считать замером Android WebView. Новая сборка и 18 JS-тестов проходят,
но физический телефон и длительный нагрев этого среза ещё не проверены.

Минимальный следующий прогон на телефоне: 60 секунд покоя и перемещений камеры
после прогрева для дня, ночи, каждого эффекта и всех эффектов вместе; оба режима
качества. Затем 10 минут с эффектами, уход/возврат из фона и холодный запуск без
сети. Записать модель телефона, ОС, версию WebView и p95; целевой бюджет —
не более 40 мс p95 при ограничении 30 FPS. Не считать успешную сборку доказательством
плавности на устройстве.

Следующая художественная итерация использует утверждённый дневной/ночной референс:
12 широких рёбер Байтерека, семь оформленных зданий на прежних местах, новые кроны,
крупные секции фасадов и выборочный свет в окнах. Это первый 3D-проход, не точное
совпадение с картинкой. Дополнительно устранены найденные источники мерцания:
совпадающие высоты дорожек/дорог, недостаточная точность глубины камеры и наложение
материалов частей зданий. 20 JS-тестов включают регрессии этих правил.
Результат на физическом Android/iPhone пока не подтверждён.

### Этажи и помещения — 16.11.2026

В City Preview появилась кнопка **«Этажи · тест»**. Это тот же `VenueBrowser`,
который используется в реальной карточке здания и форме события, но с изолированным
репозиторием в памяти. Все планы/события явно тестовые, схема не является планом MEGA.

Проверка вручную: «Без плана» → события здания; «План v1» → «1 этаж» → нажать
зал на схеме или в списке → создать тестовую встречу → открыть её из списка.
«План v2» добавляет 2 этаж в том же экране; для него намеренно отсутствует рисунок.
«Всё здание» возвращает все привязанные события. Перезапуск очищает тестовые данные.
Это проверка UI, а сетевое обновление тем же клиентом отдельно покрыто
`VenueHttpSimulationTest` через локальный Postman-сервер.

Новая сборка успешно установлена на API 36; автоматический UI-прогон не завершён:
доступ к снимку окна есть, но управление нажатиями отклонено системой. Не считать
успешную сборку доказательством визуальной проверки плана.
