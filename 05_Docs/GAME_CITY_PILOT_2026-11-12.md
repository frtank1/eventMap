# Игровой город: мобильный пилот и обновления контента

Дата: 12 ноября 2026. Это первый технический срез, а не перенос всей презентации в production.

## Что добавлено

- В мобильной вкладке карты есть отдельный вход **«3D-город · пилот»**. Старый провайдер карты не удалён.
- Встроенный Three.js-движок и локальная резервная сцена: Байтерек, Ак Орда, Астана Арена.
- Улицы, обычные здания и зелень подгружаются по открытым векторным данным. Архитектура трёх достопримечательностей — собственные стилизованные модели из прежнего макета, не сторонние купленные модели.
- Масштабирование, перемещение, вращение двумя пальцами, переходы к трём зданиям, день/ночь и базовая сезонная палитра.
- Нажатие на модель/подпись/землю передаёт выбранную точку нативному экрану. Карточка показывает реальные доступные события в радиусе 150 м и кнопку создания.
- Форма создания получает координаты и название. Остальной черновик не стирается; повторный вход в композицию не перезаписывает исправленную точку; незавершённая публикация защищена от замены места.
- Фиолетовые маркеры — данные EventRepository, без демонстрационных событий. Нажатие открывает существующий экран события/рилсов. Обновление раз в 30 секунд при активном экране, а не realtime-подписка.
- Статические пешеходы/оживление окружающей среды не означают реальных пользователей или посещаемость.

## Как устроено обновление без новой мобильной сборки

В приложение **один раз** попадает движок и встроенный резервный пакет. После этого `GET /world/manifest.json` сообщает, какие файлы данных использовать. Меняются серверные данные, не JS приложения.

1. Приложение сразу рисует встроенные здания.
2. Если есть проверенный дисковый пакет, переключается на него.
3. Загружает manifest и проверяет совместимость/лимиты.
4. Получает необходимые hash-named файлы, сверяет длину, SHA-256 и структуру геометрии.
5. Создаёт новую геометрию до удаления прежней. Только целый валидный пакет становится активным.
6. Одна транзакция IndexedDB сохраняет последний пакет. Сбой/недостаток места не удаляет встроенный резерв. При невозможности записи UI честно сообщает «без дискового кэша».

Откат — публикация старого manifest со старыми hash-файлами. Номер release — метка, не монотонный счётчик: откат разрешён.

**Без обновления приложения:** геометрия/скалярные материалы трёх пилотных зданий в поддерживаемой схеме, метаданные; события через существующий API.

**С обновлением движка:** новые механики, загрузчики/форматы, новые типы эффектов, расширение списка разрешённых сетевых хостов. Схема v1 пока НЕ содержит анимационные клипы, аудио, текстуры, сценарии или шейдеры.

Добавление массового каталога новых зданий, перенос всех анимаций и изменение границ исключения обычной застройки — следующий этап. Не считать данный пилот готовой системой стриминга всех авторских моделей города.

## Публичный контракт данных

База берётся из `CoreConfig.baseUrl`; в проекте это корень Render без `/v1`.

| Запрос | Ответ | Кэш / доступ |
|---|---|---|
| `GET /world/manifest.json` | JSON schemaVersion=1, engineVersion=1, release, models[] | `no-cache`, без авторизации |
| `GET /world/assets/{sha256}.json` | Только JSON геометрии | `public, max-age=31536000, immutable` |
| неизвестный файл/путь | 404 | JS и произвольные пути не раздаются |

У `/world/*` CORS `*` без credentials: это только публичные архитектурные данные. Существующий API сохраняет свой CORS whitelist. `nosniff` на контенте. Тест проверяет, что WebView origin не получает доступ к соседнему закрытому CORS-маршруту.

Manifest: обязательны `schemaVersion`, `engineVersion`, `release` (1–64 ASCII-символа), `models` (1–12). Каждая запись: `id`, `title`, `lat`, `lng`, `height`, `radius`, `file`, `sha256`, `bytes`. `file` строго `assets/<sha256>.json`; внешние URL/обход каталогов запрещены. Координаты ограничены областью Астаны. Лимит файла 6 MiB, суммарно 18 MiB.

Модель: `schemaVersion:1`, `id`, `materials[]`, `meshes[]`. Материалы — только числовой цвет/emissive/roughness/metalness/opacity, boolean transparent, side 0/2. Mesh: positions, normals, indices, material, detail. Не больше 250 тыс. вершин и 45 объединённых мешей на здание. Конечные числа, корректные индексы и границы проверяются до создания GPU-ресурсов. Никакого `eval`, ObjectLoader пользовательского JSON, удалённого JS или shader-кода.

SHA-256 — целостность, не подпись издателя. Доверие к издателю обеспечивается HTTPS и заранее разрешённым хостом. Для масштабного CDN-канала следует добавить подписанный manifest и ключи выпуска/ротацию.

## Мост в мобильное приложение

Android: локальный движок через WebViewAssetLoader HTTPS-origin; origin-scoped WebMessageListener; запрет file/content access и mixed content. iOS: локальный WKWebView с ограничением read-access на папку ресурсов, main-frame и точный URL в обработчике сообщений; внешние навигации запрещены.

Нативный код передаёт публичные точки событий и настройки. JS возвращает только ограниченные сообщения `ready/place/event/status/content/error`. Токены, создание события, платежи и API-авторизация остаются в Kotlin. Приём событий проверяет, что ID есть в уже загруженном списке.

Связь «здание → события» сейчас **по расстоянию**, а не постоянный placeId в базе. Выбор Ак Орды/стадиона не даёт разрешение на мероприятие, не подтверждает бронирование и не обходит модерацию.

## Сборка и контентные выпуски

Из `02_Code/game-city`:

```sh
npm ci
npm test
node --experimental-vm-modules check-export.mjs
npm run build
```

`build` собирает локальный `preview-dist`, копирует встроенный runtime в Compose resources и исходный контент в ресурсы backend. Запускается перед мобильной сборкой при изменении ДВИЖКА/резервной сцены. Тестовая панель QA в мобильную сборку не включается.

Проверка в браузере: `npm run preview`, адрес `http://127.0.0.1:8784`. Верхние QA-кнопки меняют только память loopback-сервера; ни backend, ни production они не изменяют. `pilot-2` слегка меняет цвет Ак Орды; `offline` даёт 503 только канала контента (не имитирует полное отсутствие интернета); `incompatible` даёт неподдерживаемую версию.

Для нового пакета после изменения исходных моделей:

```sh
npm run export
npm test
npm run stage-content -- content/manifest.json --release=astana-2026-11-13
```

`stage-content` сверяет хеши/схему, добавляет immutable файлы и последним атомарно меняет backend manifest. **Он не пересобирает и не меняет встроенные ресурсы мобильного приложения.** Затем требуется обычный deploy backend; мобильный релиз не нужен. Старые hash-файлы сохранять для отката. В перспективе тот же контракт переносится на object storage/CDN, с атомарным переключением указателя manifest.

В этой работе remote deploy, push в GitHub и публикация сайта НЕ выполнялись. Частный Sites-макет не используется как CDN и не менял доступность. До deploy `/world` приложение остаётся на встроенных моделях, даже если production вернёт 404.

## Проверки и честные ограничения

На 12.11.2026:

- JS: 9 тестов — обновление/откат, cold-cache fallback, порча хеша/кэша, несовместимость, лимиты, таймаут, ошибка GPU/диска, конкурентное обновление.
- Kotlin: 25 тестов модулей map/event UI проходят, включая мост и перенос точки в форму. Android debug APK собирается.
- Backend: 34 теста проходят, включая точные хеши отдаваемых ресурсов, cache headers, CORS и запрет произвольных путей.
- Живой браузер: pilot-1 → pilot-2 без перезагрузки движка; отказ сервера → сохранён pilot-2; повторный запуск при отказе → pilot-2 из IndexedDB; несовместимый пакет отклонён; откат на pilot-1; выбор Ак Орды передал её координаты.
- Postman: локальный GET manifest, статус/версия/количество/пути/лимиты — пройден. Это не проверка production deployment.
- iOS модуль карты компилируется; полный `ComposeApp` debug framework для iOS Simulator успешно слинкован. Это не запуск iOS приложения. Попутно добавлены три ранее недостающих импорта `Foundation.timeIntervalSince1970`, блокировавших iOS-компиляцию напоминаний/камеры/временного медиа.
- После разблокировки Mac APK открыт в Android-эмуляторе `emulator-5554` (API 36): приложение запускается, экран входа отображается. Вход демо-аккаунта остановлен сетевой ошибкой: в логе `ConnectTimeoutException` для `/auth/login`, лимит подключения 20 секунд; UI показывает `No internet connection`. Это не ответ о неверном пароле.
- Независимая проверка `GET https://eventmap-guo1.onrender.com/health` с Mac: Postman завершился по таймауту (exit 1; проверка ожидаемого HTTP 200 не получила ответа). Повторная транспортная диагностика curl: TCP 0,026 с, TLS 0,056 с, за 55 с ни одного байта HTTP-ответа, exit 28. DNS и TCP/443 из эмулятора доступны. Причина на уровне сервера или сетевого пути пока не установлена; это не доказательство глобального падения Render.
- Нативные сценарии «3D-город → карточка → форма», жесты и background/foreground пока НЕ пройдены: обычный вход не завершился. Авторизация не обходилась, аккаунты и события не создавались, production не менялся. Состояние экрана сохранено в `02_Code/game-city/test-results/native-login-blocked-phone.png` (локальное QA-свидетельство, каталог игнорируется Git).

Скорость настоящего телефона не измерена. Ограничены DPR до 1,5, рендер до 30 кадров/с, 2 одновременных запроса улиц, 9 требуемых тайлов, 16 в памяти. Детали моделей скрываются на расстоянии; невидимые тайлы освобождаются. Эти ограничения НЕ гарантируют 30 fps на среднем Android.

**Офлайн гарантируется резерв трёх зданий, а не вся Астана.** Уличные векторные тайлы пока без собственного постоянного offline-кэша. Нативный IndexedDB/WKWebView cache и жесты требуют прогона на телефонах; desktop-браузер не заменяет этот прогон.

Следующий контрольный этап: восстановить доступ к API или подключить отдельное тестовое окружение, завершить вход в установленном APK; проверить точку → карточку → форму → публикацию только в тестовом окружении, background/foreground, повторный запуск, память и FPS на среднем Android и iPhone. После этого — CDN, пакеты районов, настоящий LOD, отсечение вне кадра и перенос анимаций/пространственного аудио из макета.

Применённые рабочие навыки: API Engineer/Documentation/Testing задали контракт и негативные проверки; Sites использован только для локальной адаптации исходного макета, без публикации.
