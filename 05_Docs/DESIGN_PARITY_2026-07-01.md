# Соответствие дизайна ↔ мобилки ↔ бэка · 2026-07-01

Дизайн: `EventMap Prototype.dc.html` (шэренная версия = локальная копия в корне, 25 экранов).
Мобилка: `02_Code` (CMP, Voyager). Бэк: `04_Backend/server` (Ktor, миграции V1–V8).

## Вывод в одну строку

Бэк покрывает дизайн лучше всего (~80% механик), мобилка имеет почти все экраны, но половина из них на моках, а 8 эндпоинтов, которые зовёт мобилка, на бэке не существуют.

## 1. Критично: мобилка зовёт несуществующие эндпоинты

| Мобилка зовёт | На бэке | Что есть вместо |
|---|---|---|
| `GET /notifications`, `GET /feed` | ❌ нет | только push-регистрация `POST /push/register` |
| `GET /search` | ❌ нет | ничего (в API_CONTRACT §G есть) |
| `GET /subscriptions`, `subscription-requests/{id}/approve|reject` | ❌ нет | только `POST/DELETE /organizers/{id}/subscribe` |
| `GET /users/me`, `GET /users/{id}/history` | ❌ нет | `GET /game/profile` (XP/уровень) |
| `POST /events/{id}/ticket` | ❌ нет | `POST /events/{id}/tickets/purchase`, `GET /tickets/my` |

Экраны Notifications (F4), Subscriptions (F1), Search (G2), Profile (H1) в мобилке при живом бэке упадут/будут пустыми.

## 2. Критично: фичи бэка, не подключённые в мобилке (UI на моках)

## 3. Дизайн-фичи, отсутствующие с обеих сторон

- Режимы карты «Пульс / Поток / Туман» как визуальные слои (C1 G1–G3): на мобилке только пульсирующие LIVE-пины; «Поток» нет и на бэке.
- Тепловая карта C11, «Карта днём» C2 (дневная тема), спонтанная карточка «⚡ 34 человека собрались» (бэк /map/pulse близко, но эндпоинта агрегации «без события» нет).
- Квест-компас «движ по вкусу · 320 м» на карте.
- Слои в фильтрах C8 (кружки live-видео, люди, тепло, 18+) — в MapFiltersScreen только базовые фильтры.
- Экран оценки P4 как отдельный флоу с тег-чипсами («🔥 Атмосфера»…): бэк принимает `POST /events/{id}/rating`, мобилка шлёт из Detail/Reel, но отдельного экрана с тегами нет; поле тегов на бэке — проверить.
- LIVE-шторка C5 с кружками участников — частично (EventDetail есть, кружков нет).

## 5. Где всё сходится ✅

- Онбординг + интересы (A2–A8): экраны есть, `POST /auth/interests` есть с обеих сторон.
- Карта с пинами событий: `GET /events` → MapViewModel (с demo-fallback), LIVE-пульс пинов.
- Рилс/видео D1: `GET /videos/now`, `POST /videos/react`, подписка на организатора — есть везде.
- Запись и публикация E3: RecordVideo/VideoEdit + `media/presign|confirm` + `POST /videos`.
- Оплата P1/P2: purchase есть; модель `TicketGuest(userId|null)` на бэке точно повторяет дизайн («друг увидит билет» / «+N анонимно»). Способы оплаты (Kaspi/карта) — на бэке оплата пока не подключена (render.yaml: free-режим без оплаты).
- Квест-механика на бэке 1:1 с дизайном: `condition: geo|photo|purchase`, `orderedChain`, приз, счётчик финишёров, prizeQr.

## Честный чек-ин квестов (доделано 01.07.2026, вторая итерация)

- **Гео**: новый `GeoProvider` в `common/core/platform` (expect/actual): Android — LocationManager.lastKnownLocation (разрешение запрашивает MainActivity, манифест дополнен), iOS — CLLocationManager one-shot c ожиданием ответа на диалог разрешения (Info.plist дополнен), desktop/wasm — null. Чек-ин geo/photo шлёт реальные координаты устройства; нет гео → понятная ошибка, сервер больше не получает координаты точки.
- **Фото**: чек-ин photo — выбор снимка из галереи (FileKit, как обложка в CreateEvent) → `media/presign` → PUT в storage (клиент named "upload" без bearer) → `media/confirm` → `mediaUrl` в чек-ин. Лимит 8 МБ, стадии в CTA («Определяем позицию…» / «Загружаем фото…» / «Проверяем…»).
- Осталось по чек-инам: камера вместо галереи (сейчас только галерея, как во всём приложении), QR-сканер (ввод кода вручную), `getCurrentLocation` вместо lastKnown на Android (на свежем девайсе lastKnown может быть пуст).
