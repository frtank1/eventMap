## Критические проблемы (P0 — чинить сразу)

### 1. Нет git-репозитория
Код не под версионным контролем. `ci.yml` не работает, истории изменений нет, один сбой диска = потеря всего. **→ `git init`, push на GitHub, включить CI.**

### 2. Клиент сломается через час работы
Клиент при 401 зовёт `POST auth/refresh` (KtorModule), но на бэкенде эндпоинта `/auth/refresh` нет. Access-токен живёт 3600 с → через час любой залогиненный пользователь принудительно разлогинивается. **→ реализовать `/auth/refresh` первым делом.**

### 3. Refresh-токены небезопасны
`JwtService.generateRefresh` создаёт токен **без срока жизни**, он нигде не хранится → отозвать невозможно, `/auth/logout` отсутствует. Плюс: дефолтный `JWT_SECRET = "dev-secret-change-me"`, CORS `anyHost()`. **→ таблица refresh-токенов (expiry 30 дн, ревокация), logout, secret только из env, CORS по whitelist.**

### 4. Бэкенд не соответствует собственному контракту
- `GET /events` отдаёт **всю таблицу** — без bbox, фильтров и пагинации (контракт требует PostGIS bbox).
- `POST /events` отсутствует — клиентский визард создания события (D6–D8) не на что опереться.
- `startAt`/`endAt` — varchar вместо timestamp, PostGIS не подключён.
- `forgot/reset/interests`, `participants/media/ratings/attend/purchase` — заглушки, возвращают 200/пустоту. Заглушка `purchase` отвечает `{"status":"paid"}` — опасно забыть.
- `SchemaUtils.create` вместо миграций. **→ Flyway + типы дат + bbox-запрос + POST /events.**

## Важные проблемы (P1)

### 5. Тесты почти отсутствуют
Клиент: 6 тест-файлов на ~10 200 строк (только core + example). Бэкенд: 0 тестов. Папка 07_Testing пуста. **→ минимум: тесты use-case'ов бэкенда (auth) и ViewModel-ов карты/событий.**

### 6. ViewModel-ы нарушают собственные конвенции
`MapViewModel` не наследует `BaseScreenModel` (требование ERRORS.md), создаёт свой `CoroutineScope` без отмены (утечка), ошибки сети молча глотает и остаётся на `sampleEvents()` — пользователь никогда не узнает, что данные демо. **→ перевести на BaseScreenModel, демо-фолбэк вынести в data-слой за явный флаг `demoMode`.**

### 7. Логирование токенов
Ktor client: `LogLevel.ALL` — access/refresh-токены и тела запросов попадают в логи на проде. **→ `LogLevel.ALL` только в debug-сборке.**

### 8. N+1 в EventRepositoryImpl
Имя организатора тянется отдельным запросом на каждую строку события. **→ join.**

### 9. distanceKm всегда 0.0
При маппинге событий с бэка расстояние захардкожено `0.0` → фильтр радиуса на карте фиктивен. **→ считать от локации пользователя (haversine) или возвращать с бэка.**
