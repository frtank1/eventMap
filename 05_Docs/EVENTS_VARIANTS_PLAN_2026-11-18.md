# Как добавляются события: варианты и порядок работ (18.11.2026)

Основа уже есть: Event Model V2 на сервере (миграции V13, V15).

- **`kind`**: `planned`, `gathering`, `live_signal`, `private`.
- **`sourceType`**: `organizer`, `business`, `government`, `initiator`, `witness`.
- **Участие и доступ**: `joinPolicy`, `audience`, `minAge`.
- **Для живых сигналов**: `expiresAtMs`, подтверждения, `proofMediaId`.
- **Прочее**: заявки на участие, билеты, рейтинги, привязка к зданию, этажу и помещению (`buildingId`, `floorId`, `roomId`).

Каналов добавления, очереди модерации и уровней показа на карте пока нет.

## 1. Одно событие — пять осей вариантов

| Ось | Варианты |
|---|---|
| Кто добавил | редакция (подборка со ссылкой на источник) · гость без аккаунта (предложение) · пользователь · свидетель («здесь сейчас») · проверенный организатор или бизнес · площадка (внутри своего здания) · город |
| Тип | по расписанию · встреча своих · живой сигнал (сгорает через N часов) · приватное |
| Где | точка · здание · этаж или помещение · территория (полигон с входами) |
| Когда | разово · несколько дней · повторяется (например, каждую субботу) · прямо сейчас |
| Как видно на карте | **S** шарик с обложкой · **M** территория, зоны и входы · **L** своя 3D-сцена из шаблона (`event-scene.js`) |

## 2. Доверие и модерация по источнику

| Источник | Как публикуется |
|---|---|
| Редакция | Сразу. Бейдж «Подборка», ссылка на источник обязательна |
| Гость без аккаунта | Только через очередь модерации |
| Пользователь | Приватное и встреча своих — сразу и только для приглашённых. Публичное — через модерацию, пока у автора нет истории |
| Свидетель | Сразу, но бледным сигналом. Ярче становится по подтверждениям, сам гаснет через N часов |
| Проверенный организатор или бизнес | Сразу. Сцену уровня L — по заявке |
| Площадка | Свои события — сразу. Чужие события в своём здании — через очередь площадки (ADR-003, по `buildingId`) |

Демо-данные никогда не выдаются за настоящие. Симуляции и демо-сцены помечаются.

## 3. Чего не хватает в модели

- `moderationStatus`: `pending`, `published`, `rejected`, `expired`, плюс кто и когда проверил.
- `recurrence`: простое правило: день недели и время, до какой даты.
- `area`: полигон территории и точки входов (для уровня M).
- `presentation`: `S`, `M` или `L` и `sceneTemplate` с параметрами (для уровня L).
- `sourceUrl` и `sourceName` (для редакции).
- `contact` у предложения от гостя — необязательный, только для модератора, на карте не показывается.

## 4. Порядок работ

До запуска 30.11:

1. **Единая схема события и один валидатор** для сервера, веба и движка. Новые поля из раздела 3 добавить в миграцию V17. Старые клиенты продолжают работать.
2. **«Предложить событие» без аккаунта.**
   - В вебе: точка на карте → категория → дата и время → название и описание → ссылка → необязательный контакт.
   - На сервере `POST /events/suggestions`: лимит запросов по IP, ловушка для ботов, без персональных данных в ответе.
   - В админке очередь «Предложения» с кнопками «опубликовать» и «отклонить»; опубликованное появляется на карте.
3. **Редакционная подборка в том же формате**: таблица → JSON → импорт. На запуск 30–50 настоящих событий со ссылками.

После запуска:

4. Шаблоны сцен M и L: концерт, ярмарка, забег (маршрут), распродажа в ТРЦ (этаж или помещение). Организатор выбирает шаблон в форме.
5. Живые сигналы и встречи своих в приложении: подтверждения, сгорание, видимость для друзей.
6. Кабинет площадки: очередь заявок по своему зданию, решение площадки, эскалация через 48 часов.

Деплой сервера и запись в боевую базу — только с разрешения владельца. Пункты 1–3 делаются и проверяются локально.
